## 1 · Ziel dieses Schritts

Ziel war die vollständige Inbetriebnahme aller physisch installierten Hardware-Komponenten des Raspberry Pi 5: M.2 HAT Compact mit Crucial CT1000P310SSD2 (1 TB NVMe), Raspberry Pi Camera Module 3 (IMX708) sowie Raspberry Pi Sense HAT. Zusätzlich sollte das Betriebssystem von der MicroSD-Karte auf die NVMe-SSD geklont werden, um dauerhaft von der SSD zu booten und von der deutlich höheren I/O-Leistung zu profitieren.

---

## 2 · Durchgeführte Aktivitäten

- **System-Health-Check nach erstem Boot** mit neuer Hardware durchgeführt
  - Kernel: `Linux 6.12.47+rpt-rpi-2712 aarch64`
  - Temperatur: 47–48 °C, Throttling: `0x0` (kein Throttling)
  - `dmesg` zeigte keine Fehler oder Warnungen
- **SSD verifiziert** via `lsblk` und `fdisk`: `/dev/nvme0n1`, 931.5 GB, Modell `CT1000P310SSD2`
- **Sense HAT verifiziert** via Python `sense_hat`-Bibliothek (bereits installiert, Version 1.5)
  - Temperatur: ~33.8 °C, Luftfeuchtigkeit: ~27.5 %, Luftdruck: ~966.9 hPa
  - LED-Matrix zeigte grünes "OK" — alle Sensoren funktional
- **Kamera-Software installiert** — `libcamera-hello` war nicht vorhanden
  - Ursache: Befehl in neueren Versionen umbenannt zu `rpicam-hello`
  - Installiert: `rpicam-apps`, `python3-picamera2`, `libcamera-tools`, `imx500-all`
  - Nach Reboot: Kamera erkannt als `imx708_wide [4608x2592 10-bit RGGB]`
  - Testbild mit `rpicam-still --zsl -o ~/test.jpg` aufgenommen (4608×2592, 14.35 fps)
  - Bild via `scp` auf Mac übertragen und visuell verifiziert
- **SSD-Migration durchgeführt** (MicroSD → NVMe SSD, 2-Partitionen-Layout)
  - SSD neu partitioniert: `nvme0n1p1` (511 MB, FAT32, Label `bootfs`) + `nvme0n1p2` (931 GB, ext4, Label `SSD-1000GB`)
  - Boot-Partition geklont via `rsync`: 90 MB in ~2.5 Sek.
  - Root-Partition geklont via `rsync`: 11.77 GB in ~188 Sek.
  - `/mnt/ssd/etc/fstab` aktualisiert: PARTUUID durch UUID `b6c3cba2-80ff-4901-b3f5-763be1f1e0cc` ersetzt
  - `/mnt/ssd/boot/firmware/cmdline.txt` aktualisiert: `root=PARTUUID=5bafb12a-02` → `root=UUID=b6c3cba2-80ff-4901-b3f5-763be1f1e0cc`
  - Bootloader-Reihenfolge gesetzt via `raspi-config`: `BOOT_ORDER=0xf146` (NVMe → SD → USB)
  - Nach Reboot bestätigt: `findmnt /` zeigt `/dev/nvme0n1p2` als Root-Partition
- **Performance-Benchmark** durchgeführt (hdparm + dd):
  - SD Read: 87.7 MB/s → SSD Read: 444.2 MB/s (+407 %, 5.1× schneller)
  - SD Write: 63.2 MB/s → SSD Write: 210.0 MB/s (+232 %, 3.3× schneller)

## 3 · Technische Entscheide

| Entscheid | Begründung | Verknüpfung RAID |
|---|---|---|
| 2-Partitionen-Layout auf SSD (boot + root) | Pi 5 Bootloader benötigt separate FAT32-Boot-Partition; erster Versuch mit nur einer Partition schlug fehl | D-[eintragen] |
| UUID statt PARTUUID in fstab und cmdline.txt | PARTUUID ist an die physische Partition der SD gebunden; UUID ist laufwerksunabhängig und portabler | D-[eintragen] |
| MicroSD als Notfall-Fallback behalten | Sicherheitsnetz bei fehlgeschlagenem Boot; keine Daten gelöscht | D-[eintragen] |
| `rpicam-still --zsl` statt `rpicam-jpeg` | Kamera empfiehlt ZSL (Zero Shutter Lag) für beste Bildqualität beim IMX708 | — |

## 4 · Probleme & Lösungen

| Problem | Lösung / Workaround | Issue-ID (RAID) |
|---|---|---|
| `libcamera-hello: command not found` nach Installation | Befehl wurde in neueren `rpicam-apps`-Versionen zu `rpicam-hello` umbenannt | — |
| Erster SSD-Boot-Versuch schlug fehl (Pi bootete weiterhin von SD) | SSD hatte nur eine Root-Partition ohne separate Boot-Partition; SSD neu partitioniert mit korrektem 2-Partitionen-Layout | I-[eintragen] |
| `raspi-config nonint get_boot_order` nicht gefunden | Nicht verfügbar in dieser OS-Version; Boot-Order via EEPROM-Output `BOOT_ORDER=0xf146` manuell verifiziert | — |
| Luftdruck-Sense HAT beim ersten Aufruf = 0 | Sensor benötigt einen zweiten Aufruf zum Initialisieren; zweiter Aufruf lieferte korrekte 966.9 hPa | — |
