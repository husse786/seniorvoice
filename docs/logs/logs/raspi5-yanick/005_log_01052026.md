## 1 · Ziel dieses Schritts

Erste lauffähige MVP-Pipeline des SeniorVoice-Assistenten auf dem Raspberry Pi 5 implementieren und testen. Die Pipeline soll den vollständigen Sprachfluss abbilden: Audioeingabe via Webcam-Mikrofon → Speech-to-Text (STT) → LLM-Antwortgenerierung → Text-to-Speech (TTS) → Audioausgabe via Bluetooth-Lautsprecher. Architekturentscheid: Monolithische Python-Pipeline statt Docker-Microservices für den MVP, um schneller zu einem funktionsfähigen Prototyp zu kommen.

---

## 2 · Durchgeführte Aktivitäten

- Hardware-Integration auf Pi 5:
  - Logitech C920E HD Webcam via USB angeschlossen — wird als `HD Pro Webcam C920: USB Audio (hw:2,0)` erkannt, Analog Stereo Input
  - Sony SRS-XB23 Bluetooth-Lautsprecher via Bluetooth 5.0 (A2DP Sink, Codec LDAC) verbunden
  - Beide Geräte über PulseAudio Device Profiles verifiziert (Desktop via Pi Connect)
- Python-Umgebung eingerichtet:
  - venv unter `/home/admin/seniorvoice/.venv` erstellt (Python 3.13)
  - System-Dependencies installiert: `portaudio19-dev`, `pulseaudio-utils`, `alsa-utils`
  - Python-Packages installiert: `sounddevice`, `numpy`, `faster-whisper`, `piper-tts`
- Pipeline-Code lokal auf Mac entwickelt und via `scp` auf Pi deployed:
  - `pipeline/audio_capture.py` — Aufnahme vom Webcam-Mikrofon via `sounddevice`, Silence-Detection (RMS-basiert, Threshold 0.02, 2s Stille stoppt Aufnahme)
  - `pipeline/stt.py` — Transkription via `faster-whisper` (Modell: `small`, Device: `cpu`, Sprache: `de`, Compute-Type: `int8`)
  - `pipeline/llm_client.py` — HTTP-Client für Moonshot Kimi API (`kimi-k2.5`), OpenAI-kompatibles `/v1/chat/completions` Endpoint
  - `pipeline/tts.py` — Sprachsynthese via `piper` CLI mit Modell `de_DE-thorsten-medium.onnx`, Playback via `paplay` (PulseAudio → BT-Speaker)
  - `pipeline/sensor.py` — PIR-Sensor-Modul via `lgpio` (GPIO17, gpiochip4) — vorbereitet, noch nicht verdrahtet
  - `pipeline/config.py` — Konfiguration via Umgebungsvariablen
  - `pipeline/main.py` — Orchestrator mit Keyboard-Trigger (`--no-pir`) und PIR-Trigger-Modus
- Piper TTS Voice-Modell manuell heruntergeladen:
  - `de_DE-thorsten-medium.onnx` (60 MB) + `.onnx.json` von HuggingFace (`rhasspy/piper-voices`)
  - Abgelegt unter `~/.local/share/piper-voices/`
- End-to-End Test durchgeführt:
  - Gesprochene Frage: „Welcher Monat ist der Wärmste in der Schweiz?"

  - TTS: Antwort korrekt synthetisiert und über BT-Lautsprecher abgespielt

## 3 · Technische Entscheide

| Entscheid | Begründung | Verknüpfung RAID |
|---|---|---|
| Monolithische Pipeline statt Docker-Microservices für MVP | Weniger Moving Parts, schnellerer Weg zum funktionierenden Prototyp; Microservice-Split kann nach validiertem MVP erfolgen | D-06 |
| Moonshot Kimi API (`kimi-k2.5`) direkt statt via OpenClaw | OpenClaw war auf dem Pi nicht mehr installiert; direkter API-Call ist simpler und eliminiert eine Dependency | D-07 |
| Bluetooth-Lautsprecher (Sony SRS-XB23) statt 3.5mm-Klinke | Kein kabelgebundener Lautsprecher verfügbar; BT-Speaker via PulseAudio/A2DP Sink einwandfrei nutzbar | D-08 |
| Sense HAT nicht verwendet | GPIO-Pins für PIR-Sensor benötigt; Sense HAT blockiert den GPIO-Header | D-09 |
| `piper` CLI statt Python-Library-Integration | CLI-Aufruf einfacher, Output direkt als WAV-Datei, Playback via `paplay` | — |
