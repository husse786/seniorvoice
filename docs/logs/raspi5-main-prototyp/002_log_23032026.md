## 1 · Ziel dieses Schritts

OpenClaw als agentic Orchestrierungsschicht auf dem Raspberry Pi 5 (Hostname: `senioragent`) installieren, konfigurieren und erstmalig in Betrieb nehmen. Ziel war es, einen lauffähigen AI-Agenten (`SeniorAgent`) über das Terminal anzusprechen und die Grundlage für die spätere Integration von STT/TTS-Microservices zu schaffen. Dieser Schritt ersetzt die ursprünglich geplante manuelle Implementierung der Agenten-Loop-Logik in Python durch OpenClaw als fertige Orchestrierungsplattform.

---

## 2 · Durchgeführte Aktivitäten

- OpenClaw v2026.3.22 (4dcc39c) via Installationsskript auf dem Pi installiert
  - `curl -fsSL https://openclaw.ai/install.sh | bash`
- Onboarding-Wizard ausgeführt und Gateway als systemd-Daemon eingerichtet
  - `openclaw onboard --install-daemon`
  - Modell-Provider: Moonshot, Modell: `moonshot/kimi-k2.5`
- Gateway gestartet und Status verifiziert
  - `openclaw gateway start`
  - `openclaw gateway status` → Gateway läuft auf Port 18789
- Agenten-Konfiguration geprüft
  - `openclaw agents list` → Agent `main` mit Identity `SeniorAgent` bestätigt
  - Workspace: `~/.openclaw/workspace`, Agent-Dir: `~/.openclaw/agents/main/agent`
- SSH-Tunnel von Mac zum Pi für Dashboard-Zugriff eingerichtet
  - Problem: Port 18789 auf dem Mac bereits belegt → Workaround Port 18790 verwendet
  - `ssh -N -L 18790:127.0.0.1:18789 yanick@<PI_IP>`
- Terminal UI (TUI) gestartet und erste Chat-Session mit SeniorAgent durchgeführt
  - `openclaw tui`
- SeniorAgent mit Projektkontext initialisiert via Prompt:
  - Rolle: Voice Assistant für Senioren (65+), läuft lokal auf Raspberry Pi 5
  - Hardware-Kontext: Mikrofon, Lautsprecher, Kamera, Sensoren
  - Ton: warm und konversationell, präzise bei Fakten
  - Signatur-Emoji: 🚀
- Setup-Anleitung als Markdown-Datei `openclaw-setup-guide.md` erstellt für Teamweitergabe
