## 2 · Durchgeführte Aktivitäten

### Hardware-Verkabelung

- **HC-SR501 PIR-Sensor** physisch an den Pi 5 angeschlossen:
  - Signal-Pin → GPIO4 (PIN7, physischer Pin)
  - VCC → PIN2 (5V)
  - GND → PIN6 (GND)
- Kabel mit Dupont-Verbindern (Female-Female) direkt an GPIO-Header gesteckt
- Verkabelung gemäss HC-SR501 Datenblatt (`docs/hardware/MOTIONSENSOR-HC-SR501-MANUAL-23.09.2020.pdf`)
- Anfangs kein Signal auf GPIO17 — nach Vergleich mit Pinout-Diagram festgestellt: Sensor physisch an GPIO4 verdrahtet (Verwechslung Pin-Nummer vs. GPIO-Nummer)

### lgpio auf Pi 5 (RP1-Chip)

- Pi 5 verwendet neuen **RP1 I/O-Controller** statt dem alten BCM-GPIO-System
- `gpiozero` mit Standard-Konfiguration funktioniert auf Pi 5 nicht korrekt
- **lgpio** als Bibliothek gewählt: unterstützt explizite `gpiochip`-Adressierung
- Pi 5 nutzt `/dev/gpiochip4` (statt `/dev/gpiochip0` auf früheren Modellen)
- `lgpio` nur system-weit installierbar auf arm64 (kein pip-Wheel verfügbar, fehlendes `swig` für Compilation)
- Lösung: venv mit `--system-site-packages` konfiguriert, damit `lgpio` aus System sichtbar ist

### PIR-Kalibrierungstool (`test_pir.py`)

- Standalone-Skript `test_pir.py` geschrieben:
  - Öffnet gpiochip4, liest GPIO4 im Input-Mode
  - Polling-Loop mit 0.1s Interval — gibt Zeitstempel + Signal-Level aus
  - `--pin` und `--chip` als CLI-Argumente (Defaults: pin=4, chip=4)
  - Sauberes Cleanup via `try/finally` + SIGINT-Handler
- **Kalibrierung am HC-SR501:**
  - `Sx`-Potentiometer (Sensitivity): auf mittlere Position gedreht (~5–7m Reichweite)
  - `Tx`-Potentiometer (Hold-Time): auf niedrige Position (~3s Hold-Time)
  - Jumper: Single-Trigger-Mode (H-Position, kein Repeat-Trigger)
- Test: Hand-Bewegung vor Sensor → Signal wechselt zuverlässig 0→1 innerhalb <0.5s

### Integration in Pipeline (`sensor.py`, `config.py`, `main.py`)

- `config.py` Default von `PIR_GPIO_PIN=17` auf `PIR_GPIO_PIN=4` geändert
- `config.py`: `PIR_GPIO_CHIP=4` als neuer Env-Var hinzugefügt
- `sensor.py` angepasst: liest `PIR_GPIO_CHIP` aus config, übergibt an `lgpio.gpiochip_open()`
- `main.py`: `--no-pir` Flag für Keyboard-Trigger, Standard-Betrieb nutzt PIR
- Getestet: `python main.py` startet, wartet auf PIR-Trigger, Bewegung löst Aufnahme aus

## 3 · Technische Entscheide

| Entscheid | Begründung | Verknüpfung RAID |
|---|---|---|
| lgpio statt gpiozero | Pi 5 RP1-Chip erfordert explizite gpiochip4-Adressierung; gpiozero gibt auf Pi 5 keine Kontrolle über gpiochip-Auswahl | D-04 |
| PIR auf GPIO4 statt GPIO17 | Physische Verdrahtung; config.py Default angepasst | D-10 |
| venv mit `--system-site-packages` | lgpio nur system-weit auf arm64 verfügbar (kein pip-Wheel wegen fehlendem swig) | D-11 |
| Single-Trigger-Mode am HC-SR501 | Retriggered-Mode (L-Jumper) löst bei langer Anwesenheit multiple Trigger aus — für Voice-Assistant unerwünscht | — |
