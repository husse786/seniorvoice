## 1 · Ziel dieses Schritts

Das LLM-Backend von einer monolithischen Funktion in `llm_client.py` in eine eigenständige Abstraktionsschicht (`llm_backend.py`) auslagern. Ziel: (1) Fallback-Chain — wenn Ollama lokal nicht erreichbar, automatisch auf Kimi Cloud wechseln; (2) Streaming-Support damit Piper TTS Satz für Satz sprechen kann, während das Modell noch generiert; (3) Benchmark-CLI-Tool für systematischen Vergleich verschiedener Modelle.

---

## 2 · Durchgeführte Aktivitäten

### Neues Modul `llm_backend.py` — LLM-Abstraktionsschicht

- **`BackendConfig` Dataclass** erstellt mit Feldern: `name`, `api_base`, `api_key`, `model`, `timeout`
- **`_resolve_backends()`** liest `LLM_BACKENDS` Env-Var:
  - `"default"` = bestehende `LLM_API_BASE/KEY/MODEL/TIMEOUT` Vars (Backwards-Kompatibilität)
  - `"ollama,kimi"` = löst `LLM_OLLAMA_*` und `LLM_KIMI_*` Env-Vars auf
  - Reihenfolge in der Env-Var = Priorität in der Fallback-Chain
- **`_do_complete()`** — nicht-streamender HTTP-Call (urllib, OpenAI-kompatibel)
- **`_do_stream()`** — SSE-Iterator via `urllib.request.urlopen()`, yieldet Token-Strings aus `choices[0].delta.content`
- **`complete()`** — Fallback-Chain mit Fehlerbehandlung:
  - Iteriert Backends in Reihenfolge
  - Bei `URLError`, `HTTPError`, `TimeoutError`, `OSError`: nächstes Backend versuchen, Warning loggen
  - Fallback nur bei Connection-Fehler (nicht bei HTTP 4xx nach Verbindung)
- **`stream()`** — gleiche Fallback-Logik, yieldet Token-Strings
- Alle Logging via `get_logger("llm_backend")` (D-18 Structured Logging)

### `llm_client.py` refactored — Streaming + per-sentence TTS

- Import: `from llm_backend import complete as llm_complete, stream as llm_stream`
- **`chat()`** (non-streaming): unveränderte externe API, intern nutzt `llm_complete()`
- **`chat_streaming()`** (neu):
  - Ruft `llm_stream()` auf, akkumuliert Tokens in Buffer
  - Regex `[.!?]\s` erkennt Satzenden
  - Bei vollständigem Satz: `speak(sentence)` aufrufen (TTS) — User hört ersten Satz während LLM noch generiert
  - Resttext am Ende ebenfalls sprechen
  - Returniert `(full_reply, updated_history)` wie `chat()`
- **`main.py`** erweitert: `LLM_STREAM` Env-Var steuert ob `chat()` oder `chat_streaming()` aufgerufen wird

### `config.py` — Multi-Backend Env-Vars

- `LLM_BACKENDS = os.getenv("LLM_BACKENDS", "default")` — Fallback-Chain-Konfiguration
- `LLM_STREAM = os.getenv("LLM_STREAM", "false")` — Streaming-Toggle

### Benchmark-CLI-Tool `benchmark_models.py`

- CLI-Script für systematischen LLM-Vergleich auf dem Pi
- **Eingabe:** Liste von Modellnamen als Positional-Args (Ollama-kompatible Namen)
- **Testset:** 4 feste deutsche Prompts (Alltagsfragen für Senioren):
  1. `"Erkläre mir kurz, was Diabetes ist."`
  2. `"Mein Knie tut weh. Was kann ich tun?"`
  3. `"Wie koche ich Kartoffelsuppe?"`
  4. `"Erinnere mich daran, dass ich um 15 Uhr meine Pille nehmen muss."`
- **Metriken pro Run:** `tokens_per_second`, `ttft_ms` (Time To First Token), `total_ms`, `token_count`, `response_text`
- **Mehrere Runden** via `--rounds N` (Default: 3) — Durchschnitt + Einzelergebnisse
- **Cold-Start-Markierung:** erste Runde nach Modell-Unload als `is_cold_start=True`
- **Modell-Unloading** zwischen Modellen: `keep_alive=0` Ollama-Parameter
- **Output-Formate:** Tabellen (rich-ähnliches ASCII), `--json` für JSON-Export
- Kein pip-Dependency auf `rich` — reines stdlib-ASCII-Formatting

## 3 · Technische Entscheide

| Entscheid | Begründung | Verknüpfung RAID |
|---|---|---|
| `llm_backend.py` als eigenständige Abstraktionsschicht | Minimale Klassen-Overhead-freie Lösung; `complete()` + `stream()` als einfaches Interface ohne Klassen-Vererbung | D-20 |
| `LLM_BACKENDS=ollama,kimi` Env-Var für Fallback-Reihenfolge | Config-driven, null breaking changes (default = bisheriges Verhalten) | D-21 |
| Named Backend Config via `LLM_{NAME}_*` Env-Vars | Folgt bestehendem Env-Var-Muster; keine Config-Files nötig | D-22 |
| Streaming via urllib SSE Line-Iteration | Keine neuen Dependencies; Ollama nutzt Standard OpenAI-SSE-Format | D-23 |
| Sequentielles per-sentence TTS (kein Threading) | `speak()` ist blocking + gleicher WAV-Output-Pfad; sequential ist thread-safe und einfach | D-24 |
| Fallback nur bei Connection-Fehler, nicht mid-stream | Sobald Tokens fliessen, committen wir zum Backend — mid-stream-Fallback würde Antwort inkonsistent machen | D-25 |

## 4 · Probleme & Lösungen

| Problem | Lösung / Workaround | Issue-ID (RAID) |
|---|---|---|
| Sentence-Regex `[.!?]\s` matched nicht am Satzende ohne Leerzeichen | Resttext (`buffer.strip()`) nach Stream-Ende separat sprechen — fängt den letzten Satz ohne trailing Whitespace | — |
| Ollama-Modell zwischen Runs nicht entladen | `POST /api/generate` mit `keep_alive: 0` nach jedem Modell — Ollama entlädt aus RAM | — |
| TTFT-Messung bei Streaming: erster Token = TTFT | `time.perf_counter()` vor Stream-Start, Timestamp bei erstem yielded Token — Delta = TTFT | — |
