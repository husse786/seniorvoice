## 1 · Ziel dieses Schritts

Observability und Wartbarkeit der Pipeline verbessern: alle `print()`-Statements durch strukturiertes Python-Logging mit File-Rotation ersetzen, Interaction-Timing in SQLite erfassen (Grundlage für Grafana-Dashboard), LLM-Backend auf Kimi k2.6 migrieren und Audio-Feedback-Sounds implementieren.

---

## 2 · Durchgeführte Aktivitäten

### Structured Logging (~15 Min)
- `logging_config.py` erstellt: `RotatingFileHandler` (5 MB, 5 Backups) + Console-Handler
  - Logformat: `%(asctime)s [%(name)s] %(levelname)s: %(message)s`
  - Konfigurierbar via Env-Vars: `LOG_LEVEL`, `LOG_DIR`, `LOG_MAX_BYTES`, `LOG_BACKUP_COUNT`
- `interaction_log.py` erstellt: SQLite `interactions`-Tabelle in bestehender `seniorvoice.db`
  - Schema: `trigger_type`, `user_text`, `response_text`, `stt_duration_ms`, `llm_duration_ms`, `tts_duration_ms`, `total_duration_ms`, `error`
- Alle `print()` in Pipeline-Modulen durch `log.info/debug/warning/error` ersetzt:
  - `main.py`, `audio_capture.py`, `stt.py`, `llm_client.py`, `tts.py`, `memory.py`, `sensor.py`, `sounds.py`
- `main.py`: `time.perf_counter()` Timing um STT/LLM/TTS Steps, `log_interaction()` Call nach jeder Interaktion
- `config.py`: 4 neue Env-Vars für Logging-Konfiguration
- `test_pir.py` bewusst mit `print()` belassen (interaktives Kalibrierungstool)

### Kimi Migration (~20 Min)
- `config.py`: `LLM_MODEL` Default von `kimi-k2.5` auf `kimi-k2.6` geändert
- `config.py`: `LLM_TIMEOUT` als konfigurierbare Env-Var hinzugefügt (Default 30s, erhöhbar für lokale Modelle)
- `llm_client.py`: Hard-fail bei fehlendem `LLM_API_KEY` entfernt — `Authorization`-Header wird nur gesetzt wenn Key vorhanden
  - Ermöglicht Ollama-Nutzung ohne API-Key: `LLM_API_BASE=http://localhost:11434/v1 LLM_MODEL=gemma3:4b`
- `memory.py`: Gleiche Änderung — optionaler Auth-Header, Timeout `LLM_TIMEOUT * 2` für Extraktions-Calls
- Getestet auf Pi mit Kimi k2.6: Pipeline end-to-end funktional, Long-Term Memory korrekt (Fakten Janik + Neva abgerufen)

### Audio-Feedback Sounds (~30 Min)
- `sounds.py` erstellt: Chime-Generierung via numpy (Sinuswellen → int16 → WAV)
  - Listen-Chime: Aufsteigend C5→E5 (300ms, Volume 0.3) — spielt nach PIR/ENTER-Trigger
  - Thinking-Chime: Absteigend E5→C5 (260ms, Volume 0.25) — spielt vor LLM-Call
  - Fade-in/out (10ms) gegen Klick-Artefakte
  - WAV-Cache in `/tmp/seniorvoice/sounds/` — wird beim ersten Aufruf generiert
- `config.py`: `SOUND_ENABLED` Env-Var (Default `true`)
- `main.py`: `play_sound("listen")` nach Trigger, `play_sound("thinking")` vor LLM-Call
- `test_sounds.py` erstellt: Standalone-Skript zum lokalen Testen (Mac via `afplay`, Pi via `paplay`/`aplay`)
- Sounds auf Mac mit Kopfhörern verifiziert — beide Chimes klar unterscheidbar
- Auf Pi via BT-Speaker: Listen-Chime hörbar, Thinking-Chime wird teilweise von A2DP-Wake-Latenz geschluckt

## 3 · Technische Entscheide

| Entscheid | Begründung | Verknüpfung RAID |
|---|---|---|
| Python stdlib `logging` statt Drittanbieter (loguru etc.) | Keine zusätzliche Dependency auf arm64; RotatingFileHandler deckt Anforderung ab | D-18 |
| Interaction-Logs in gleicher SQLite-DB wie Long-Term Memory | Eine einzige Datenquelle für Grafana; kein separates DB-File nötig | D-19 |
| Log-Level DEBUG für TTS/Audio-Internals, INFO für User-Events | Reduziert Log-Noise im Normalbetrieb; verbose via `LOG_LEVEL=DEBUG` aktivierbar | — |
| `LLM_API_KEY` optional (kein hard-fail) | Ermöglicht lokales Ollama ohne API-Key; beide Backends nutzen OpenAI-kompatible API | D-16 |
| Audio-Feedback via numpy-generierte Töne | Keine externen Sound-Dateien nötig; Pitch/Dauer im Code anpassbar | D-17 |

## 4 · Probleme & Lösungen

| Pi hatte `LLM_API_BASE`, `LLM_MODEL` als Env-Vars auf Ollama gesetzt (aus früherer Session) | `export LLM_API_BASE=https://api.moonshot.ai/v1` und `export LLM_MODEL=kimi-k2.6` manuell gesetzt; Vars nicht in `.bashrc`/`.profile` persistiert — verschwinden bei nächstem Login | — |
| BT-Speaker (Sony SRS-XB23) verschluckt erste ~200-300ms Audio durch A2DP-Wake-Latenz | Chimes sind zu kurz um Latenz zu absorbieren; kabelgebundene Speaker als Lösung für nächste Session evaluieren | — |
