**1 · Ziel dieses Schritts**

Ziel war die vollständige Inbetriebnahme des Raspberry Pi 4 (2 GB RAM) als Basisinfrastruktur für das Projekt SeniorVoice. Der Pi soll als lokaler, datenschutzkonformer Betriebsknoten für alle Microservices dienen. In diesem Schritt wurden Fernzugriff, Container-Runtime und der KI-Agent-Backend (OpenClaw) eingerichtet, sodass ab W02 mit der Entwicklung der Python-Microservices begonnen werden kann.

---

**2 · Durchgeführte Aktivitäten**

- Raspberry Pi 4 (2 GB) mit Raspberry Pi OS (64-bit Lite) neu aufgesetzt
- SSH-Zugriff auf den Pi eingerichtet und verifiziert
- Tailscale VPN installiert und konfiguriert für sicheren Remote-Zugriff ohne offene Ports
- Docker Engine installiert via offiziellem Installationsskript (`get.docker.com`)
  - Docker Compose Plugin v5.1.1 installiert und verifiziert
  - Funktionstest mit `docker run hello-world` erfolgreich
- Node.js 24 (v24.13.0) installiert via NodeSource-Repository (arm64)
  - npm v11.6.2 ebenfalls verfügbar
- OpenClaw 2026.3.24 installiert via `openclaw.ai/install.sh`
- OpenClaw Onboarding durchgeführt (`openclaw onboard --install-daemon`)
  - Modus: QuickStart
  - Model-Provider: Moonshot AI (`moonshot/kimi-k2.5`)
  - Web Search Provider: Brave Search (API-Key konfiguriert)
  - Channels: übersprungen (kein Messaging-Kanal benötigt, Zugriff via HTTP-API)
  - Skills: übersprungen (werden projektspezifisch konfiguriert)
  - Hooks: übersprungen
- OpenClaw Gateway als systemd User-Service installiert
  - Systemd Lingering für Root aktiviert (Gateway überlebt Logout)
  - Gateway-Status: `reachable` auf `ws://127.0.0.1:18789`
- SeniorAgent-Identität via TUI (`openclaw tui`) initialisiert
  - Identity-Prompt eingespielt: Rolle, Zielgruppe (65+), Sprachen (DE/EN), Ausgabeformat (keine Markdown, kurze Sätze)
  - Agent antwortet korrekt auf Deutsch und Englisch in warmem, einfachem Ton
- Gateway-Token extrahiert und in `/root/seniorvoice/.env` gespeichert
  - Projektverzeichnis `/root/seniorvoice/` angelegt

**3 · Technische Entscheide**

| Entscheid | Begründung | Verknüpfung RAID |
|-----------|-----------|-----------------|
| Tailscale statt Port-Forwarding für Remote-Zugriff | Kein offener Port ins Internet; Zero-Trust-Netzwerk; einfache Einrichtung | D-01 |
| Docker via `get.docker.com` Installationsskript | Offizielle Methode für Raspberry Pi OS arm64; apt-Paket oft veraltet | D-02 |
| Node.js 24 via NodeSource statt apt | apt-Version auf Pi OS zu alt (Node.js 18); OpenClaw Gateway benötigt Node 24 | D-03 |
| Moonshot AI `kimi-k2.5` als temporärer LLM | Schnellster Weg zum lauffähigen Agenten; Ollama (lokal) als Stretch-Goal W07+ | D-04 |
| OpenClaw Channels übersprungen | SeniorVoice nutzt kein Messaging-Interface; Zugriff erfolgt direkt via HTTP-API vom Orchestrator | D-05 |

---

**4 · Probleme & Lösungen**

| Problem | Lösung / Workaround | Issue-ID (RAID) |
|---------|---------------------|----------------|
| `sudo: invalid option -- 'f'` beim Docker-Install | `sudo` entfernt — als root eingeloggt, kein sudo nötig | I-01 |
| OpenClaw Onboarding versehentlich abgebrochen | `openclaw onboard --install-daemon` erneut ausgeführt — Onboarding wiederholbar | I-02 |
| Gateway-Token in CLI-Ausgabe maskiert (`__OPENCLAW_REDACTED__`) | Token direkt aus `~/.openclaw/openclaw.json` via Python-Einzeiler extrahiert | I-03 |
| Pi 4 hat nur 2 GB RAM (Guide empfiehlt 8 GB+) | Akzeptiert für MVP; max. 2–3 Container gleichzeitig; Whisper `tiny`-Modell gewählt | R-01 |
